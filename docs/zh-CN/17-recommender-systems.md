前几章主要从内容本身学习表示；推荐系统还利用“谁与什么发生过交互”。目标不是生成任意物品，而是
在数百万候选中，为当前用户和场景找到少量真正相关的项目。一次复杂模型无法经济地给全库打分，

### 本章学到什么程度？

本章要求掌握一条最小推荐链：邻居协同过滤补评分 → 低秩向量学习偏好 → top-$K$ 召回 → 排名指标
验收。精排、多任务、在线实验和因果校正只要求理解职责与风险，不要求实现完整工业平台。

## 17.1 推荐数据为什么不是普通分类表？

用户—物品矩阵绝大多数位置为空，但“空”有两种完全不同的含义：用户看过却没点，或系统从未展示。
把所有空位标成负样本会把曝光策略的选择误当作用户偏好。

![推荐日志形成稀疏的曝光与反馈矩阵](../assets/recommender-sparse-matrix.png)

横轴是物品，纵轴是用户；有颜色的位置是系统曾曝光并观察到的反馈，大片空白是未知而非确定不喜欢。
矩阵稀疏使相似用户之间共享信息有价值，也带来选择偏差和冷启动。训练/测试若随机拆同一时段的交互，
还可能让未来行为泄漏到过去。

<details><summary>苏格拉底追问：为什么“没有点击”不能直接作为负标签？</summary>
用户可能没看到、位置太低、界面未加载或当时无需求。标签混合了偏好、曝光和界面机制，需要负采样、
曝光建模或因果方法减轻偏差。
</details>

## 17.2 协同过滤：相似行为能否互相补全？

先看最原始的邻居方法。假设小王给科幻片 A、B 分别打 5、4 分，小李给 A、B、C 打 4、5、2 分；
两人在共同看过的 A、B 上偏好相似，因此可以用小李相对自己平均分的偏差，估计小王对 C 的评分。
步骤是：只取共同评分物品 → 计算去均值后的相似度 → 找给 C 评过分的相似用户 → 对他们的评分偏差
加权平均。若没有足够共同评分，邻居相似度就不可靠，此时应回退到用户均值、物品均值或内容特征。

邻居方法直接使用原评分；矩阵分解则进一步假设，庞大的评分表可以由少数潜在因素近似解释：

显式评分矩阵 $R\in\mathbb R^{M\times N}$ 可近似为低秩乘积

$$\hat R=UV^\top,
\qquad U\in\mathbb R^{M\times d},\ V\in\mathbb R^{N\times d}.$$

用户 $u$ 与物品 $i$ 的分数

$$s(u,i)=p_u^\top q_i+b_u+b_i+\mu.$$

只对观测集合 $\Omega$ 优化平方损失：

$$\min_{U,V}\sum_{(u,i)\in\Omega}(R_{ui}-p_u^\top q_i)^2
+\lambda(\|U\|_F^2+\|V\|_F^2).$$

可用交替最小二乘（固定一边解另一边）或 SGD。潜向量维度不必对应人工命名主题；它只需让交互可
预测。隐式反馈更常用加权平方损失、BPR pairwise loss 或采样 BCE。

### 一个可手算的协同过滤预测

设用户向量 $p_u=[1,0.5]$，物品 $q_A=[0.8,0.2]$、$q_B=[0.1,1]$，不计偏置。
$s(u,A)=0.9$，$s(u,B)=0.6$。若用户对 B 的目标为 1，平方损失 $L=(1-s_B)^2/2$，则

$$\frac{\partial L}{\partial p_u}=(s_B-1)q_B=[-0.04,-0.4],\quad
\frac{\partial L}{\partial q_B}=(s_B-1)p_u=[-0.4,-0.2].$$

梯度下降后用户和 B 的向量彼此靠近。一次交互同时改变“用户喜欢什么”和“物品被什么用户喜欢”，
这正是协同信号能跨用户共享信息的原因。

## 17.3 隐式反馈与负采样

对一次正交互 $(u,i^+)$，BPR 希望正物品高于采样负物品 $i^-$：

$$L_{BPR}=-\log\sigma(s(u,i^+)-s(u,i^-))+\lambda\|\theta\|^2.$$

负采样分布会改变模型学到的任务：均匀采样强调长尾区分，按热度采样产生更难负例，却可能进一步
强化流行偏差。采样 loss 不能直接解释为全库校准概率；上线排序还要根据候选分布重新评估。

若 $s^+=2,s^-=1$，BPR 损失 $-\log\sigma(1)\approx0.313$。对分数差 $\Delta$，
$\partial L/\partial\Delta=\sigma(\Delta)-1\approx-0.269$，梯度下降会提高正分、降低负分。
困难负样本信号更强，也更可能是假负样本。

## 17.4 一次矩阵分解训练发生了什么？

![矩阵分解训练曲线与学习到的物品向量](../assets/matrix-factorization-training.png)

左图是观测曝光上的 BCE 加正则，下降说明优化器在拟合已记录反馈；右图把物品 latent vector 的
前两维画出，用于观察相近物品。训练 loss 下降不能证明对未曝光物品有效，也不能证明二维坐标具有
人工可命名含义；需要按时间的全库排名评测。

运行：

```bash
python code/chapter17/recommender_systems.py
python code/chapter17/course_lab.py
```

第一个脚本生成稀疏日志、矩阵分解曲线与排名图。第二个课程实验先在一个 $4\times4$ 评分表上完成
user-based CF 预测，再用 BPR 学习用户/物品向量，把未参与训练的正物品作为未来测试项，计算
Recall@5 与 NDCG@5。典型结果中 BPR loss 从约 0.69 降到 0.06，Recall@5 明显高于随机召回。

在这个最小实现中，用户向量和物品向量就是只使用 ID 的两座塔；工业双塔只是把查表扩展为能读取
内容与上下文的神经编码器。这个对应关系能帮助理解结构，但不能据此认为矩阵分解已经解决冷启动。

## 17.5 双塔召回：怎样从百万物品中快速找候选？

用户塔编码历史、画像和上下文得到 $p_u$，物品塔编码 ID、内容和统计得到 $q_i$，用点积或余弦分数
训练。物品向量离线入 ANN 索引，在线只算用户向量并查 top-$K$。

$$s(u,i)=f_\theta(u,context)^\top g_\phi(i).$$

这与第 13 章语义检索同构，但正样本来自行为日志，负样本受曝光机制影响。双塔速度快，缺点是用户
与物品在最后点积前几乎不发生细粒度交互，通常只承担召回。

## 17.6 精排：不仅预测点击

精排模型读取用户、物品、场景和交叉特征，可用 GBDT、Wide & Deep、DeepFM 或 Transformer。
若只优化点击率，系统可能偏好标题党。实际常预测多个目标：点击、观看时长、购买、退款、长期留存，
再按业务效用和约束组合：

$$score=w_1P(click)+w_2\mathbb E[watch]-w_3P(refund).$$

权重来自业务价值、实验和约束，而不是随意调到离线分数最高。多任务梯度还可能冲突，需要检查每个
目标和人群，而非只看总 score。

## 17.7 排序指标怎样理解？

Recall@$K$ 看相关物品是否进入候选，Precision@$K$ 看前 $K$ 的相关比例，MRR 强调第一个相关项，
NDCG 允许多级相关并对靠前位置折扣：

$$DCG@K=\sum_{r=1}^{K}\frac{2^{rel_r}-1}{\log_2(r+1)},
\qquad NDCG@K=\frac{DCG@K}{IDCG@K}.$$

![排序位置越靠前获得越高权重](../assets/ranking-metric-discount.png)

柱高表示位置折扣，红点是相关物品。相关项排在第 1 位比第 20 位贡献大，符合首屏注意力。但离线
相关标签本身受旧系统曝光影响；NDCG 提升不自动等于用户长期满意。

## 17.8 为什么离线准确率会强化流行偏差？

![历史曝光集中于热门物品](../assets/recommendation-exposure-bias.png)

红线是典型头部集中的日志曝光概率，绿线是均匀参考。模型从红线数据学习，更容易预测热门物品，
又把它们展示得更多，形成反馈回路。长尾、新物品和少数兴趣缺少数据，不代表没有价值。

缓解思路包括探索流量、位置/曝光 propensity、逆倾向加权、内容特征、冷启动专门通道、多样性重排
和长期 A/B 指标。倾向估计错误也会引入高方差，因果校正不是免费修复。

## 17.9 离线验证与在线实验

推荐通常按时间切分：训练早期交互，验证稍后，测试未来。候选集合必须接近线上规模；只在 100 个
随机负样本中排名会显著高估全库性能。对同一用户的未来序列，还要避免使用未来聚合统计。

线上 A/B 观察点击、时长、转化、留存、投诉、延迟与生态指标。短期点击提升可能损害长期留存；
实验需预注册主指标、护栏、样本量和停止规则，避免每天偷看后提前结束。

### 一次完整推荐请求经过什么

1. 读取用户最近行为与当前场景；新用户走冷启动策略。
2. 协同、内容、热门、探索等多路召回候选并去重。
3. 精排预测点击、时长、购买；所有特征必须在请求时可得。
4. 重排加入多样性、库存、安全、公平与频控。
5. 返回列表并记录 request、曝光位置、模型/特征/索引版本。
6. 延迟反馈到达后按事件时间构造训练样本。

召回漏掉的物品精排救不回来；不记录曝光位置就难区分偏好与位置偏差；不记录索引版本就无法复现。

若前三名相关等级为 $[3,0,2]$，则 $DCG@3=7+3/2=8.5$。理想顺序 $[3,2,0]$ 的
$IDCG=7+3/\log_2 3\approx8.893$，所以 $NDCG@3\approx0.956$。相关集合相同、位置不同，
Recall 不变而 NDCG 会变。

## 17.10 多样性、探索与约束重排

最终列表不仅追求相关，还可能约束类别重复、创作者曝光、新鲜度、库存、公平和安全。最大边际相关
（MMR）是一种简单重排：

$$MMR(i)=\lambda\,relevance(i)-(1-\lambda)
\max_{j\in selected}similarity(i,j).$$

$\lambda$ 大更重相关，小则更鼓励多样。探索可用 bandit 在不确定候选上收集新证据，第 18 章正式
学习探索—利用。

## 17.11 复杂度、系统成本与失败诊断

全库逐物品打分为 $O(Nd)$；ANN 降低搜索访问但有近似召回损失。在线链还包含特征读取、模型推理、
规则和网络，需报告 P50/P95/P99 延迟、吞吐、索引大小与更新新鲜度。

| 症状 | 可能原因 | 检查 |
|---|---|---|
| 离线高、线上差 | 候选不真实/曝光偏差/目标错位 | 全库回放与 A/B 分层 |
| 新物品无曝光 | ID 协同信号缺失 | 内容塔、探索和冷启动通道 |
| 列表高度重复 | 只优化点式相关 | 多样性指标与重排 |
| 用户兴趣突变响应慢 | 特征/索引陈旧 | 新鲜度与更新延迟监控 |
| 热门越来越热门 | 反馈回路 | 曝光分布、长尾覆盖、探索实验 |

时间切分还要保证 point-in-time correct：预测 6 月 1 日行为时，不能使用 6 月整月点击率。新用户
和新物品需单独分组报告。发布时先 shadow 回放，再小流量 canary/A-B，并准备旧模型与旧索引的
成对回滚。

## 17.12 与现代 AI 的联系

- **LLM 推荐**：LLM 可理解内容、生成解释或作为重排器，但全库召回仍需高效向量/协同方法。
- **生成式推荐**：把物品 ID token 化并自回归生成候选，共享序列建模思想；约束、去重和库存仍需系统层。
- **RAG**：文档召回与物品召回共享双塔、ANN、hard negative 和排名指标。
- **多模态商品表示**：文本、图像、价格和行为共同编码，内容改善冷启动但会带来模态偏差。
- **在线学习**：策略影响下一批数据，推荐比静态分类更容易产生反馈回路和因果问题。

## 17.13 苏格拉底导师

<details><summary>矩阵中未观测位置为什么不是零评分？</summary>
未观测可能只是没有曝光；将其设零会混淆偏好与旧系统策略。
</details>

<details><summary>低秩分解为何能补全？</summary>
它假设用户和物品交互由少数潜在因素决定，使已观测交互约束未观测点的内积。
</details>

<details><summary>双塔 Recall@100 高，为什么最终推荐仍可能差？</summary>
相关物品可能精排错误、列表重复、目标与满意度错位，或候选标签受曝光偏差污染。
</details>

<details><summary>随机负采样比例改变，BCE 概率还能直接上线吗？</summary>
通常不能。采样改变类先验，输出排序可用但概率需校准或修正，并在真实候选分布验证。
</details>

<details><summary>为什么不能只用随机数据划分？</summary>
它可能让未来行为、物品热度和用户统计进入训练，无法模拟真实向未来推荐。
</details>

<details><summary>A/B 点击率提高就能发布吗？</summary>
还需看统计不确定性、长期留存、投诉、公平、延迟等护栏和新奇效应。
</details>

## 17.15 面试八股

- **协同过滤核心？** 利用用户—物品交互相似性，而不只依赖内容。
- **矩阵分解学什么？** 用户和物品低维向量，使内积重构观测偏好。
- **显式与隐式反馈？** 评分是显式，点击/观看是隐式且受曝光影响。
- **BPR？** 用正物品与采样负物品的分数差做 pairwise logistic 排序损失。
- **为什么多阶段推荐？** 全库精排太贵，召回先缩小候选，精排再建复杂交互。
- **双塔优缺点？** 可离线索引、高效召回；查询—物品交互受点积瓶颈限制。
- **Recall/NDCG 区别？** 前者关注是否召回，后者还考虑多级相关与位置折扣。
- **曝光偏差？** 只观察旧策略展示后的反馈，数据并非随机抽样。
- **冷启动？** 新用户/物品缺乏协同行为，可用内容、热门先验、探索与问卷。
- **离线与在线指标为何不一致？** 日志偏差、目标代理、系统延迟和用户反馈回路不同。
- **怎样避免信息泄漏？** 按时间切分，所有聚合特征只使用预测时点之前的数据。
