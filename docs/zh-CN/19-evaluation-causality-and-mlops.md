## 从第 18 章自然走到这里

前面学会了训练模型和策略，但真实失败往往不在算法公式：标签含义改变、训练/线上特征不一致、
评测数据污染、指标和业务目标错位、上线分布漂移，或相关关系被误当成因果。本章建立交付闭环：
问题定义 → 数据契约 → 无泄漏评估 → 因果边界 → 可复现发布 → 线上监控 → 回滚与再训练。

### 本章学到什么程度？

本章不是完整的统计推断、因果推断或运维课程。入门目标是养成四个动作：先写决策代价；给模型差值
而不是孤立分数加区间；区分预测相关与干预因果；把发布写成有门槛和回滚的状态机。倾向评分、双重
稳健、实验平台和集群运维只作扩展方向，不要求本章掌握。

## 19.1 先问：模型输出将改变什么决策？

“预测准确率提高”不是完整目标。需要写清：谁在何时使用输出，阈值触发什么动作，FP/FN 各造成
什么代价，真实标签多久到达，以及哪些人群不得受到不公平伤害。若模型只排序，概率校准可能次要；
若概率进入贷款额度或医疗资源分配，校准和不确定性至关重要。

<details><summary>苏格拉底追问：为什么不能先训练一个模型，再看哪个指标好看？</summary>
指标选择若发生在结果之后，会产生选择偏差；更重要的是，模型可能优化了与实际决策代价无关的代理。
应先定义决策、主指标、护栏和切分，再训练比较。
</details>

## 19.2 区分度与校准是两件事

### 阈值必须来自代价，而不是默认 0.5

假设 1000 人中模型在阈值 0.5 时得到 TP=80、FP=40、FN=20、TN=860。若漏掉一个正例代价为
100，误报代价为 10，总代价为 $20\times100+40\times10=2400$。降低阈值后若 TP=95、FP=100、
FN=5、TN=800，总代价为 $5\times100+100\times10=1500$；准确率可能下降，决策却更好。

阈值应只在验证集上依据成本或约束选择，再在测试集冻结评估。部署后类别基率改变，即使模型排序
不变，最优阈值和校准也可能改变。

AUC 衡量正样本分数高于负样本的概率，基本不受单调变换影响；校准要求预测 0.8 的样本中约 80%
发生正类。Brier score 为

$$Brier=\frac1m\sum_i(p^{(i)}-y^{(i)})^2.$$

![相同排序能力可以具有不同概率校准](../assets/calibration-reliability.png)

横轴是分箱平均预测概率，纵轴是实际正类比例，虚线是完美校准。绿色模型贴近对角线；红色模型对同一
排序做过度尖锐变换，AUC 不变但概率偏离真实频率。本章代码中两者 AUC 约相同，而过度自信模型的
Brier 更差。这说明“分类排序好”不能代替概率可信。

校准必须在独立数据上做，如 Platt scaling、isotonic 或 temperature scaling；再用另一独立测试集
报告，不能在同一集合拟合校准器又评价。

## 19.3 指标必须带不确定性与分组

单个平均值隐藏样本波动和子群体差异。可用 bootstrap 对 IID 样本估计区间；患者/用户重复记录时
应按实体 cluster bootstrap；时间序列需 block/bootstrap 或时间窗口评估。还应报告不同地区、设备、
语言、类别频率和时间段，但避免在小分组上给出虚假精确结论。

比较模型时报告效应差值与区间，而不只给两个重叠分数。大量指标和切片会增加偶然发现，应预先指定
主分析并对探索结果明确标注。

## 19.4 相关不等于干预效果

### 先画变量，再决定控制什么

以“优惠券是否提高购买”为例：用户活跃度 $U$ 同时影响发券 $A$ 与购买 $Y$，是混杂；打开优惠券
页面 $M$ 是发券后的中介；只记录成功支付用户形成的变量 $C$ 可能是碰撞点。估计总效应时应处理
前置混杂 $U$，不应机械控制中介 $M$，也不应只在 $C=1$ 人群分析。DAG 的用途不是画漂亮箭头，
而是公开识别假设，并指出哪些效应从现有数据根本不可识别。

预测问题问“看到 $X=x$ 时 $Y$ 多大”，因果问题问“如果强制采取 $A=a$， $Y$ 会怎样”。写作

$$p(Y\mid A=a)\neq p(Y\mid do(A=a))$$

提醒两者不同。混杂变量同时影响处理和结果，会让观察相关偏离因果效应。

![聚合相关与按混杂变量分组后的关系可能相反](../assets/confounding-simpson.png)

左图只看总体，对照组混入更多高基线群体，于是总体上处理组反而更差；右图按群体分层后，两个群体中
处理组都更好。这是一个受控的 Simpson 悖论示例。分层并非万能：只有控制了
足够的前置混杂，且没有错误控制碰撞变量或中介，才有因果解释。

随机实验通过分配机制打断混杂，是上线策略比较的金标准；不能实验时需明确 DAG、可交换性、positivity
和一致性等假设，使用匹配、加权、回归或 doubly robust 方法，并做敏感性分析。

## 19.5 数据契约与泄漏审计

每个特征需记录：定义、类型、单位、允许范围、缺失含义、生成时间、可用时间、来源和负责人。
**event time** 是现实事件发生时间，**processing time** 是系统写入时间；预测时只能使用当时已到达
的信息。常见泄漏包括：

- 标签之后生成的字段，如出院后诊断码预测入院风险；
- 全数据拟合标准化、PCA、词表或目标编码；
- 同一患者、视频或近重复文档跨集合；
- 未来窗口统计或回填后的“完美”历史数据；
- LLM benchmark 出现在预训练/微调语料。

应做 point-in-time join、实体分组、去重/污染检测和 feature availability 单元测试。

## 19.6 分布漂移：什么变了？

- Covariate shift： $p(x)$ 变， $p(y\mid x)$ 相对稳定。
- Label/prior shift： $p(y)$ 变。
- Concept drift： $p(y\mid x)$ 变，最危险且常需新标签确认。
- Data quality failure：类型、单位、缺失或管道本身坏了，不应都叫漂移。

![训练与当前特征分布发生变化](../assets/feature-drift.png)

蓝色是训练期特征，橙色是当前线上分布；均值、方差都发生变化。它说明输入需要调查，却不能单独证明
模型质量下降：变化可能落在无关特征，也可能模型仍稳健；反之 $p(x)$ 不变时概念也可能漂移。

PSI、KS、Wasserstein、分类器二样本检验各有假设与样本量敏感性。监控应结合特征重要性、分群、
预测分布和延迟标签质量。

一个实用排查顺序是：schema/单位是否坏 → 样本量是否足够 → 季节性基线是否匹配 → 哪些重要特征
漂移 → 预测与置信度是否变 → 延迟标签质量是否下降。只有最后几步提供证据时才决定重训。自动“漂移
即重训”可能把管道故障或坏标签写回模型。

## 19.7 从 notebook 到可复现发布

最小版本链包括：代码 commit、数据 snapshot/查询、环境、特征定义、随机种子、配置、模型权重、
指标与审批记录。训练管道应区分可复用组件：验证数据 → 构造特征 → 训练 → 离线评估 → 打包 →
部署前验证。

模型注册表保存版本和阶段；模型卡记录用途、训练数据、指标、子群体、限制、伦理和联系方式。CI 可
检查代码与小数据，持续训练/评估才决定新模型是否超过发布门槛。可复现不是“同一随机种子绝对逐位
相同”，而是环境、随机性与容差都被记录并能解释差异。

## 19.8 安全部署：shadow、canary 与回滚

- Shadow：新模型接收线上请求但不影响用户，比较输出和性能。
- Canary：只给小比例流量，监控护栏后逐步扩大。
- A/B：随机分流估计产品干预效应，需要样本量与实验治理。
- 回滚：保留上一稳定版本、兼容特征和明确触发条件。

高风险系统还需要人工复核、拒绝自动化、审计日志和 kill switch。发布流程必须演练故障，而不是把
回滚写在文档里从不测试。

发布应是一台状态机：`candidate → shadow → canary 1% → 10% → 50% → full`。每个迁移都有最低
观察时长、质量/延迟/安全门槛与自动停止条件；任一护栏越界进入 `rollback`。回滚不仅切换模型，
还要保证旧特征、旧 tokenizer/索引和 schema 仍兼容。恢复时间 RTO 也应实测。

## 19.9 线上到底监控什么？

![生产监控同时覆盖数据、系统与延迟质量](../assets/mlops-monitoring-signals.png)

三行依次是有效记录率、P95 延迟和延迟到达的质量指标，红虚线为告警阈值。数据问题可先于标签发现，
延迟恶化会直接影响用户，即使模型数学输出不变；最终业务质量通常晚几天才知道。单一 dashboard
无法替代分层告警和事件响应。

监控四层：

1. 数据：schema、缺失、范围、类别、新鲜度、漂移；
2. 模型：预测/置信度、校准、拒答率、切片表现；
3. 系统：错误率、吞吐、P50/P95/P99、内存、GPU、成本；
4. 业务与安全：转化、留存、投诉、公平、事故。

告警需有 owner、严重级别、runbook、静默/聚合规则和事后复盘，否则只会形成告警疲劳。

## 19.10 从零实验

### Bootstrap 差值，而不是分别看两个区间

比较模型 A/B 时，对每个样本保留成对损失差 $d_i=L_{A,i}-L_{B,i}$。每次 bootstrap 重采样样本
索引并计算 $\bar d$，重复许多次得到差值分布。若 95% 区间为 $[-0.012,-0.003]$，说明 A 的平均
损失较低；若跨 0，则现有数据不足以排除无差异。患者重复记录应按患者整体重采样，否则区间会
虚假变窄。

运行：

```bash
python code/chapter19/evaluation_and_mlops.py
python code/chapter19/course_lab.py
```

第一个脚本验证“单调改变概率可保持 AUC 却损害 Brier”，并生成混杂、漂移和监控图。第二个课程
实验把四个动作接起来：在验证集按 FP/FN 成本选择阈值；在测试集比较默认阈值；对两个模型的逐样本
Brier 差做 paired bootstrap；计算 PSI；最后让候选模型通过质量、P95 和错误率发布门槛。

脚本使用合成数据，使“成本变化导致阈值变化”和“漂移不等于立即重训”可以重复观察。它没有把
bootstrap 当成因果证据，也没有让发布门槛自动证明模型安全；这些边界正是本章希望建立的习惯。

## 19.11 评估 LLM、RAG 与 Agent

开放生成不能只做精确匹配。应建立：

- 任务集：真实分布、困难反例、长尾与对抗输入；
- 分层指标：检索、引用、事实、指令、风格、安全、延迟和成本；
- 评价器：可执行规则、领域人工、模型裁判相互校验；
- 污染治理：与训练语料去重，保留私有/滚动测试集；
- 不确定性：多次采样、裁判一致性、效应区间；
- Agent 轨迹：最终结果之外检查工具选择、参数、权限、恢复与副作用。

LLM-as-a-judge 规模化方便，但有位置、长度、自偏好和提示敏感性；应用人工盲评校准，不能把裁判分数
当作无误真值。

## 19.12 复杂度与失败诊断

评估成本约为样本数 × 模型调用 × 重复次数 × 裁判成本；切片、多模型和多解码会快速放大预算。
应使用分层测试：每次提交跑小型回归集，候选发布跑完整评测，定期跑昂贵人工/红队评估。

| 症状 | 可能原因 | 修复方向 |
|---|---|---|
| dashboard 全绿但投诉上升 | 指标覆盖不足/标签延迟 | 增加用户与安全信号 |
| 离线提升无法复现 | 数据/代码/随机性未版本化 | 产物链和环境锁定 |
| 漂移告警频繁无害 | 阈值不分重要性/季节性 | 业务分层与基线窗口 |
| A/B 过早显著 | 偷看和多重检验 | 预注册样本量与停止规则 |
| LLM eval 飙升 | 污染或 judge 偏差 | 私有滚动集和人工校准 |

## 19.13 与现代 AI 的联系

- **基础模型治理**：数据谱系、评测污染、能力/安全模型卡和发布门槛比单一 benchmark 更重要。
- **RAG**：文档版本、索引新鲜度和引用证据都属于可观测系统状态。
- **Agent**：工具权限、幂等性、预算、审计与 sandbox 是模型指标之外的可靠性层。
- **推荐/RL**：模型改变曝光和数据，离线评估与因果实验必须配合。
- **端侧 AI**：设备型号、功耗、温度和离线率是分布与系统切片，不能只在服务器测试。

## 19.14 苏格拉底导师

<details><summary>AUC 很高为什么不能说明预测 0.9 可信？</summary>
AUC 只关心排序；任意单调变换几乎保持 AUC，却会改变概率尺度和决策成本。
</details>

<details><summary>发现 $p(x)$ 漂移是否应立即重训？</summary>
先检查数据管道、受影响特征和质量切片；漂移未必损害目标，盲目重训还可能吸收坏标签。
</details>

<details><summary>控制越多变量，因果估计是否越可靠？</summary>
不是。控制后处理变量、中介或 collider 会引入偏差；变量选择应由因果结构而非相关筛选决定。
</details>

<details><summary>为什么线上标签延迟时仍能监控模型？</summary>
可先监控 schema、漂移、预测分布、系统指标和代理护栏，等标签到达再回填校准与质量。
</details>

<details><summary>固定随机种子是否等于完全可复现？</summary>
不等于。硬件、库、并行归约和数据版本仍会改变结果，应记录环境和容差并报告多种子统计。
</details>

<details><summary>模型裁判和人类裁判谁更可靠？</summary>
二者各有偏差；应按任务抽样校准一致性，用可执行事实检查和领域专家补充，而非盲信单一来源。
</details>

## 19.16 面试八股

- **AUC 与校准区别？** AUC 衡量排序，校准衡量概率与真实频率一致性。
- **怎样给指标区间？** 按采样单位选择 bootstrap/解析方法，重复实体需 cluster 处理。
- **数据泄漏？** 训练得到部署时不可获得的信息，包括预处理和跨实体重复。
- **三类漂移？** covariate、label/prior 和 concept drift，另需区分管道故障。
- **相关与因果？** 条件观察分布不等于干预分布，需随机化或明确识别假设。
- **Simpson 悖论？** 聚合趋势可能与每个分组趋势相反，常由群体构成/混杂造成。
- **shadow/canary/A-B？** 无影响观察、小流量发布、随机实验，回答的问题不同。
- **模型注册表保存什么？** 可追溯版本、产物、指标、阶段和审批。
- **线上监控层次？** 数据、模型、系统、业务/安全。
- **为何需要回滚？** 新模型可能在未覆盖条件下失败，恢复时间是可靠性的一部分。
- **LLM judge 风险？** 位置、长度、自偏好、提示和领域盲点，需要人工校准。
